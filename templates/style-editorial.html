01 — 产品概览

它是什么？

GrowthOS 是一个基于 Model Context Protocol (MCP) 构建的开源分析服务器。 它为 AI 应用提供标准化的数据采集、处理和可视化接口，让任何接入 MCP 协议的 AI 助手都能即时获取用户行为数据、转化漏斗和留存分析。

核心理念很简单：让数据不再是分析师的专属工具，而是 AI 的原生能力。开发者只需几行配置，就能让 Claude、GPT 等大模型直接查询生产数据库、生成分析报告，甚至自动触发运营动作。

🔌

MCP 原生集成

通过标准 MCP 协议与 AI 模型无缝通信，无需自建 API 层

📊

实时数据管道

支持 ClickHouse、Postgres、BigQuery 等主流数据源的实时连接

🤖

自然语言查询

用日常语言描述分析需求，AI 自动生成 SQL 并返回可视化结果

🛡️

权限沙箱

内置行级安全策略，确保 AI 只能访问被授权的数据范围

"未来的数据分析不是 SQL 技能竞赛，而是你能否用一句自然语言说清楚——'过去七天新用户留存为什么掉了？'" —— GrowthOS 开源社区宣言

03 — 功能拆解

架构与能力矩阵

GrowthOS 的架构分为三层：MCP 协议层负责与 AI 模型通信； 查询引擎层处理 SQL 生成、权限校验和结果缓存； 数据连接层对接各类数据库和数据仓库。三层解耦设计使得每一层都可以独立扩展和替换。

07 — SWOT 分析

优势、风险与机遇

✦ 优势 Strengths

  • MCP 协议先发优势，生态位明确
  • Rust 核心引擎性能领先竞品 3-5 倍
  • Apache 2.0 许可，社区贡献门槛低
  • 权限沙箱设计成熟，企业级安全就绪

✦ 劣势 Weaknesses

  • 团队规模小（核心开发者仅 5 人）
  • MCP 协议本身仍在快速迭代，存在兼容风险
  • 可视化能力相比成熟 BI 工具仍有差距
  • 文档和示例覆盖度有待提升

✦ 机会 Opportunities

  • AI Agent 爆发式增长，MCP 成为事实标准
  • 企业对"对话式 BI"需求旺盛
  • 开源社区可撬动数据厂商官方适配
  • 与 LLM 厂商合作预集成的可能性

✦ 威胁 Threats

  • 大厂（Google、Microsoft）可能推出封闭方案
  • 传统 BI 工具快速跟进 MCP 集成
  • 数据安全法规趋严，合规成本上升
  • MCP 协议若分裂将导致生态碎片化

10 — 结语

一个值得关注的信号

GrowthOS 的出现不是偶然。当 AI 从"聊天"走向"行动"，它需要的不仅是语言理解，更是对数据世界的深度感知。 这个项目正在回答一个根本性问题：当 AI 成为你的数据分析师，工具应该如何存在？

答案可能是：工具应该消失在对话里。GrowthOS 正在朝着这个方向走，而它脚下的 MCP 协议，可能就是通往那个未来的路。
